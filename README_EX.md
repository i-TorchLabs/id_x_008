## 一、项目背景与目标

### 1.1 业务痛点

经管学院 国际事务办公室「活动预约」长期依赖邮件 / 微信人工协调：

- 学生侧：找不到咨询入口、不知道哪些校友可约、约完后忘记时间。
- 管理侧：用登记表手工记录报名、排期靠逐条录入、统计靠人肉汇总 Excel。
- 顾问侧：预约变动靠管理员口头转告，信息滞后。

### 1.2 建设目标

构建一套线上化的「一对一预约平台」，实现 **咨询主题发布 → 时段排期 → 人员预约 → 邮件提醒 → 取消与反馈 → 数据汇总导出** 的全流程闭环，让三类角色各取所需、各得其所。

### 1.3 系统定位

本次汇报所涉的系统，覆盖学生端与管理端双端，并打通 CUHK 统一身份认证（SSO）与校园邮件触达链路。

## 三、功能拆解

按用户使用旅程，将本系统拆解为 8 个功能模块。

### 3.1 模块 A · 登录与认证

- 管理员：用户名 + 密码登录，按角色自动跳转（admin → 后台，user → 学生端）。
- 学生：跳转 CUHK ADFS 统一身份认证，首次登录自动建档，无需注册。
- 登出：管理员清空本地存储返回登录页；学生额外调用 ADFS 登出。

### 3.2 模块 B · 学生端 — 活动浏览

- 活动首页：顶部品牌条，支持按时间区间 + 活动名筛选，右上角「My Records」入口。
- 列表视图：分页展示未来活动，含日期、时段、状态标签、已报 / 名额、Apply 按钮。
- 日历视图：FullCalendar 周 / 月 / 日切换，按状态着色，点击跳转报名页。
- 状态判定：Open（可报且距开始≥1 天）/ Full（已满）/ Closed（距开始<1 天或已结束）。

### 3.3 模块 C · 学生端 — 活动报名

- 活动详情：展示活动名称、富文本内容、日期与状态。
- 话题选择：结构化话题清单单选，已占用选项置灰。
- 提交报名：校验同周唯一规则，生成订单号（R+8 位数字），自动归档学生信息。
- 报名通知：成功后给学生和顾问各发一封通知邮件。

### 3.4 模块 D · 学生端 — 报名记录管理

- 我的报名：分页展示历史报名（订单号、时间、活动名、状态）。
- 取消报名：活动结束前 4 小时内禁取消；二次确认后删除记录并发送取消邮件给双方。

### 3.5 模块 E · 管理后台 — 项目管理（咨询主题）

- 项目列表：分页展示，支持按更新时间筛选，含 Edit / Delete 操作。
- 新增 / 编辑：弹窗表单：名称、富文本内容、名额、所属顾问（下拉）。
- 删除项目：二次确认，级联删除其下所有活动与报名（⚠️ 无回收站）。

### 3.6 模块 F · 管理后台 — 活动管理

- 活动列表：分页展示，含名额、已报人数、活动 / 报名时间、报名链接、明细入口。
- 新增 / 编辑：弹窗表单：关联项目、活动起止时间、报名起止时间（校验开始 ≤ 结束）。
- 批量上传：下载 14 天模板 → 填写 → 上传 .xlsx，命中已有则更新，否则新增。
- 报名明细：新窗打开，顶部四宫格摘要 + 分页报名表格。
- 删除活动：二次确认，级联删除该活动下所有报名。

### 3.7 模块 G · 管理后台 — 数据导出

- 报表导出：按时间筛选 + 勾选活动名（支持全选），点击 Export 下载 Excel。
- 联动查询：勾选活动后底部表格实时刷新对应报名明细。
- Excel 字段：序号、活动名、订单号、姓名、学号、邮箱、时间、信息。

### 3.8 模块 H · 定时邮件自动化

由服务器 cron 调度，无需用户触发。

表 3-1 定时邮件任务

| 任务 | 周期 | 触发条件 | 收件人 |
|------|------|----------|--------|
| 顾问提醒 | 每天 21:00 | 活动开始日 = 明日 | 顾问（CC careersme） |
| 学生提醒 | 每天 21:00 | 活动开始日 = 明日 | 学生（CC careersme） |
| 反馈问卷 | 每 2 小时 | 活动结束 ≥ 2 小时且未发过 | 学生 |

- 问卷邮件去重：同一报名仅发一次。

## 四、核心业务规则

业务规则集中可审计，是本次研发任务的「产品契约」。

### 4.1 时间规则

表 4-1 时间规则一览

| 规则 | 取值 |
|------|------|
| 同周预约限制 | 同一 ISO 自然周仅可预约 1 次 |
| 报名截止时间 | 活动开始前 24 小时（批量上传默认） |
| 学生自助取消截止 | 活动结束前 4 小时内禁取消 |
| 状态切换（Open → Closed） | 距活动开始 < 1 天 |
| 活动列表可见性 | 仅展示未来活动（开始时间 ≥ 当日） |

### 4.2 状态机

```text
活动状态（学生侧展示）
   ┌────────┐  距开始≥1天 且 未满   ┌────────┐
   │ Closed │ ◀────────────────── │  Open  │
   └────────┘                     └────────┘
                                        │ 报名人数 ≥ 名额
                                        ▼
                                   ┌────────┐
                                   │  Full  │
                                   └────────┘
```

### 4.3 唯一性与级联规则

表 4-2 唯一性与级联规则

| 对象 | 唯一约束 | 删除级联 |
|------|----------|----------|
| 项目 | name 唯一 | 删除项目 → 删除其下活动与报名 |
| 活动 | name + project_id + 时段 | 删除活动 → 删除其下报名 |
| 用户 | username + name + email | — |

## 六、异常与边界处理

表 6-1 异常处理策略

| 场景 | 系统行为 |
|------|----------|
| 未登录访问管理接口 | 返回 401 |
| 同周重复报名 | 返回 403 + 提示历史预约信息 |
| 活动 / 用户不存在 | 返回 404 |
| 取消不存在的报名 | 返回 404 |
| 邮件发送失败 | 记录日志，不影响主流程 |
| 文件格式错误 | 返回 400 |
| 服务器错误 | 统一返回 500 |
| 前端接口异常 | Message 弹窗提示 |
| SSO 未绑定密钥 | 重定向回 SSO 登录页 |

## 七、系统价值

本次研发任务实现「三个升级」：

1. **学生侧**：把"对接"从邮件 / 微信沟通升级为自助式在线预约，降低协调成本。
2. **管理侧**：将人工登记表升级为结构化数据，支持批量排期与一键导出，提升运营效率。
3. **顾问侧**：通过邮件自动触达，让顾问无需登录即可掌握预约动态。
